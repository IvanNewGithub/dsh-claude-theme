# DSH LAN Access

在同一个 Wi-Fi 下，用手机打开这台电脑上的 DSH。扫侧栏「手机访问」里的二维码就能用，不用另外装 App，也不用开公网隧道。

## 装

```bash
dsh plugin --profile web add <本仓库路径>/plugins/lan-access
```

然后重启 DSH。

插件依赖 `uqr`，已经写进 `package.json` 的 `dependencies`。如果你不是走上面的正常安装，而是用 `link:` 指到源码目录，请先在对应的 profile 里把这个依赖装上。

## 用

1. 点侧栏底部的「手机访问」。
2. 打开「局域网访问」开关。
3. **重启 DSH**，让新的监听地址生效。
4. 再打开面板，用手机扫二维码。手机必须和电脑在同一个网络。

面板打开时会取一次最新链接；页面可见时还会定时同步，所以 DSH 重启后不用手动找新二维码。

不用手机访问时，把开关关掉再重启，就恢复为只允许本机访问。

## 这条链接很重要

二维码里的链接带访问凭证。**谁能拿到它，谁就能控制这台机器上的 agent，包括执行命令和读写文件。**

- 别把链接或二维码发给别人，也不要公开分享截图。
- 只在可信网络里开，比如家里的 Wi-Fi；别在公共网络上开。
- DSH 重启后，旧链接会失效，需要重新扫面板里的二维码。

## 它是怎么做到的

插件没有另起一个代理，也没有复制一套手机界面。它做的是两件事：

1. 告诉 DSH 监听一个实际的局域网地址，让手机连得上。
2. 把 DSH 官方生成的带凭证地址交给 `uqr` 画成二维码。

链接和二维码由宿主侧一起生成、一起返回，浏览器直接显示，不会各刷各的。开关状态会写进当前 profile 的 `cordis.patch.yml`；关闭开关时会移除插件写入的配置块。

`dsh 0.2.1-rc.2` 起，webserver 不允许监听 `0.0.0.0`，所以插件选择一个具体的局域网地址，而不是直接监听所有网卡。

## 文件

```
lib/index.js    宿主侧：管理开关、生成链接和二维码
lib/client.js   浏览器侧：侧栏入口和手机访问面板
test/           测试
```

## 测试

```bash
node plugins/lan-access/test/verify-host.mjs
node plugins/lan-access/test/verify-qr.mjs   # 需要 zbarimg
```

`verify-host.mjs` 检查开关写入、回滚、地址变化和面板状态。`verify-qr.mjs` 会把生成的二维码交给真正的解码器读一遍，确认扫出来的还是原来的链接。
